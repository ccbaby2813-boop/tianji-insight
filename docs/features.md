## 1. 命理推演系统

### 1.1 功能概述

命理推演是天机推演的核心功能，用户输入问题后，系统基于易经人格调用 AI 生成个性化推演报告。

### 1.2 推演流程

```
用户输入问题
    ↓
检查登录状态 → 未登录 → 引导登录
    ↓
检查建档状态 → 未建档 → 引导建档
    ↓
原子扣减 10 积分 → 积分不足（402）→ 引导签到/看视频
    ↓
计算易经人格（lunar-javascript）
    ↓
调用 DeepSeek API 生成报告
    ↓
保存推演记录
    ↓
更新卦卡收集
    ↓
返回结果
```

### 1.3 推演类型

| 类型 | 说明 | 消耗规则（v17.0 积分制） | 报告长度 |
|------|------|----------|----------|
| 普通推演 | 基础 AI 报告 | 10 积分/次（签到/看视频/注册获取积分） | ≤700 字 |
| VIP 超级推演 | 深度分析 + 68 时空变量 | 不扣积分：VIP 优先扣每日 1 次，其次签到赠次；免费仅签到赠次 | 1000-2000 字 |

### 1.4 推演报告结构

```markdown
# {卦名} 卦推演报告

## 一、卦象解读
- 卦象含义
- 当前运势

## 二、问题分析
- 针对用户问题的具体分析

## 三、行动建议
- 短期建议（1 周内）
- 中期建议（1 月内）
- 长期建议（3 月内）

## 四、注意事项
- 需要避免的事项
- 幸运方位/颜色/数字
```

### 1.5 技术实现

- **卦象计算**：`lunar-javascript` 库
- **AI 生成**：DeepSeek API
- **报告存储**：MySQL `tuiyan_records` 表
- **积分扣减**：普通推演原子扣 10 积分（`points` 字段，见 2A 积分体系）
- **并发控制**：Redis 信号量限流（普通推演每进程 100 并发 / VIP 每进程 20 并发）

## 2A. 积分体系（v17.0）

### 2A.1 规则总览

| 行为 | 积分 | 说明 |
|------|------|------|
| 每日签到 | +10 | "我的"页，每日一次 |
| 连续签到每满 7 天 | +100 并赠 1 次深度解读 | 7/14/21...天均触发；赠次永久有效 |
| 看激励视频广告 | +10 | 仅微信小程序端；接口 30 秒冷却防刷 |
| 新用户注册 | +10 | 所有登录注册入口统一 |
| 普通推演 | -10 | 原子扣减，不足返回 402 引导获取积分（仅免费用户；VIP 按次数制） |
| 深度解读 | 0 | VIP 优先扣每日 1 次，其次签到赠次；免费仅签到赠次 |

### 2A.2 前端入口

- **"我的"页积分区**（诗集式）：大字积分余额 + "签到 +10"（印章图标）/"看视频 +10"（仅小程序）细金胶囊按钮 + 连签天数/赠次提示
- **首页推演按钮**：不再展示积分说明（积分体系说明已移至「关于我们」页）；积分不足弹窗引导"看视频+10 / 去签到"
- **激励视频**：`utils/rewardAd.js`（adUnitId `adunit-b1076c917f651348`），完整看完才发放奖励，失败自动 load→show 重试

### 2A.3 技术实现

- **接口**：`GET /api/points/balance`、`POST /api/points/checkin`、`POST /api/points/ad-reward`（`src/routes/points.js`）
- **流水**：`points_transactions` 表全量记录（checkin/checkin_streak/ad_reward/new_user/consume_tuiyan/refund_tuiyan/admin_adjust）
- **Redis**：`extra_vip_decode:*`（连签赠次，永久）、`ad_reward_cd:*`（30 秒冷却）
- **管理后台**：用户列表积分列（可排序）、用户详情积分/连签信息、积分流水 Tab

## 5. 易缘传书系统

### 5.1 功能概述

卦格匹配社交功能，用户可以找到与自己卦格相合的朋友，写信交流。

### 5.2 匹配池

**展示规则**：
- 游客可浏览候选人资料
- 显示卦格、五行、基本信息
- 不显示详细报告

**匹配算法**：
- 基于五行生克关系
- 考虑卦格兼容性
- 随机排序避免重复

### 5.3 启封功能

**说明**：消耗次数查看完整匹配报告

**报告内容**：
- 两人卦格关系
- 五行生克分析
- 相处建议
- 注意事项

### 5.4 写信功能

**发送信件**：
1. 选择好友
2. 输入信件内容
3. 点击发送

**话题模板（v1.4→v1.5 从"抒情"→"话题"）**：
- 模板按**话题族分组**：聊人格☯ / 聊缘分💞 / 聊节气🍃 / 聊推演🎲 / 走心💌，顶部标签栏点击切换
- **动态注入真实数据**：个性化模板含占位符，选中时由 `renderTemplate()` 替换——
  - 来自我的卦象（经 profile 的 `ming_ben_gua` 定位 `/api/gua/{id}`）：卦名 `{guaName}`、自嘲标签 `{ziChaoBiaoQian}`、天赋 `{talent}`、盲点 `{blindspot}`、历史人物对标 `{liShiRenWu}`
  - 来自当前节气（`/api/solar-term/current`）：节气名 `{termName}`、宜行 `{termAction}`、推荐食材 `{termFood}`
  - 来自匹配结果（`/api/relationship/{myGua}/{otherGua}`，我的卦 vs 对方卦，对方卦经收信人 openid→profile 的 `ming_ben_gua` 定位）：关系名 `{relationshipName}`、匹配等级 `{matchLevel}`、一句话 `{oneLiner}`
  - **取不到的字段回退通用文案，不报错**，保证任何情况下模板都能落笔
- **设计原则**：每个模板都遵循"我的真实信息 + 开放问句"结构，给收信人可接话的点，避免"模板痕迹重、话题终结"
- 应用模板时保留"称呼 + 落款 + 农历日期"框架，仅替换中间正文；已写内容时弹窗确认替换

**收件箱**：
- 显示未读/已读状态
- 可回复信件

### 5.5 举报拉黑

**举报**：
- 举报违规用户
- 管理员审核后处理

**拉黑**：
- 拉黑后不再收到对方信件
- 对方出现在匹配池时自动过滤

### 5.6 技术实现

- **匹配记录**：`match_records` 表
- **信件**：`letters` 表
- **举报**：`letter_reports` 表
- **拉黑**：`letter_blocks` 表
- **好友列表**：`/api/letter/friends` 接口

## 7. 分享系统

### 7.1 分享类型（v3.6 三种分享）

| 类型 | 分享内容 | 落地页 | 接收者打开看到 |
|------|----------|--------|---------------|
| 推演结果（`result`） | 分享者当时的完整推演记录 | `result.html?sid=&rid=` | 完整推演记录（判词/卦象/人格标签/历史对标/宜忌/详细解读），只读，**不设"和 TA 易缘匹配"按钮** |
| 匹配结果（`match_result`） | 分享者当时的双方匹配结果 | `match.html?sid=` | 完整匹配结果（双卦交辉+关系名+等级+分析/共鸣/冲突/建议，折叠区默认展开） |
| 个人人格（`match`） | 分享者易经人格 | `match.html?sid=` | 分享者人格（卦符/卦名/昵称）+ 引导"打开 App 与 TA 匹配" |

**分享语义**（用户锁定）：
1. 推演结果分享 → 接收者看到的就是那份推演结果页（照 APP `pages/result` 1:1 深色水墨）；
2. 匹配结果分享 → 接收者看到的就是那份匹配结果页（照 APP `sub/match/match` 1:1 宣纸主题），匹配结果来自静态关系数据，不依赖双方在线；
3. 个人人格分享 → 接收者进入双方匹配（需接收者自己卦象）。

### 7.2 分享参数（分享码 scene 约定）

| 类型 | `type` | `scene` |
|------|--------|---------|
| 推演结果 | `result` | 推演记录 ID |
| 匹配结果 | `match_result` | `guaA:guaB`（分享时双方卦组合） |
| 个人人格 | `match` | 空 |

```javascript
// 生成分享短码（需登录）
const res = await api.requestWithAuth('/api/share/code', 'POST', {
  type: 'match_result',
  scene: '19:19'   // 匹配结果分享示例：guaA:guaB
});
// res.data.share_id → 拼落地页 URL
```

### 7.3 深链支持

- **落地页 → App 唤起**：非微信环境数据渲染后 800ms 自动唤起 `tianji://result?sid=&rid=` 或 `tianji://match?sid=`；微信内置浏览器拦截 scheme，落地页顶部引导条 + 全屏遮罩引导「右上角···→在浏览器打开」。
- **App 端解析**：`app.js` `_registerDeepLink()`（`wx.miniapp.registOpenURL`）监听唤起，`handleScene()` 冷启动兜底；按 resolve 返回的 `type` 分流——`match_result` 用 scene 双方卦象直接展示该份匹配结果，`match` 用接收者自己卦实时匹配，`result` 展示只读推演结果页。

### 7.4 发送端 6 渠道

- 分享面板 `sub/profile/share/index.js`（`env.CHANNEL==='google'` 走面板）+ `utils/share-logos.js`（base64 真实 logo）。
- 微信：`wx.miniapp.shareWebPageMessage`（预填文字+链接）；WhatsApp `whatsapp://send?text=`；Facebook `fb://share/?link=`；Messenger `fb-messenger://share?link=`；X `twitter://post?message=`；Telegram `tg://msg_url?url=&text=`。
- 微信开放平台第三方 App 已配各渠道 URL Scheme 白名单（构建时写入 AndroidManifest，需重新构建 APK 生效）。

### 7.5 技术实现

- **小程序分享**：`onShareAppMessage` / `open-type="share"`
- **App 分享**：`wx.miniapp.shareWebPageMessage`（Donut）
- **分享码接口**：`POST /api/share/code`（需认证）+ `GET /api/share/resolve/:shareId`（公开，按 type 返回完整数据）
- **落地页**：`_backend_src/web/result.html` + `_backend_src/web/match.html`（部署到服务器 `projects/web/`，**勿误传 `projects/tianji-tuiyan/web/`**）
- **分享组件**：`share-button` / `share-poster` / `share-logos` 组件

## 8. 用户封禁系统

### 8.1 封禁规则

**封禁条件**：
- 发布违规内容
- 恶意举报他人
- 滥用系统功能

**封禁效果**：
- 所有 API 请求返回 403（`USER_BANNED`）
- 无法登录、无法使用推演/匹配/写信等任何功能
- 封禁状态缓存 60s（`tianji:cache:ban:{openid}`）

### 8.2 封禁流程

```
管理员后台封禁
    ↓
更新 users.status = 0
    ↓
写入 admin_logs
    ↓
Redis 缓存封禁状态（60s TTL）
    ↓
用户下次登录时检查
```

### 8.3 解封流程

```
管理员后台解封
    ↓
更新 users.status = 1
    ↓
写入 admin_logs
    ↓
清除 Redis 缓存
    ↓
用户可正常登录
```

### 8.4 技术实现

- **状态字段**：`users.status`（1=正常 0=封禁）
- **缓存**：`tianji:cache:ban:{openid}`
- **审计日志**：`admin_logs` 表
- **检查时机**：登录时、推演时、匹配时
